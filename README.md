# WAP CPD Events App

A mobile-friendly web app for WAP Medical Supplies (CPD provider ORG01637) that manages CPD attendees from advance RSVP through arrival, session completion, mandatory feedback and certificate release.

First event: **Clinical Update on Rhinosinusitis**, Friday 23 October 2026, Epikaizo Guest House, Outapi. Event details are configurable in the staff Settings page for future events.

Website: https://wapadverts-droid.github.io/wap-cpd-events-app/

## Status: LIVE (since 16 October 2026)

Real RSVPs are taken at the website above. Bookings from every phone go to one shared database (Supabase project `wap-cpd-test`, now serving the live record), so staff see all bookings and the 50-place limit holds for everyone. Earlier test bookings are archived in the same database (record `main`) and are not shown.

Automatic emails (confirmation, waiting list, place offers) are sent through the WAP Gmail account via Google Apps Script (`server/email-script.gs`; Supabase secrets `EMAIL_SCRIPT_URL` and `EMAIL_SCRIPT_KEY`; up to 100 recipients a day). Known limits: WhatsApp messages are prepared for staff to send by hand; QR scanning reads a photo rather than a live camera feed; HPCNA requirements for certificate content have not been checked against current official guidance. Data is stored in Supabase's European region (accepted by WAP).

Future changes are rehearsed in practice mode (staff: Settings → Practice mode) before being uploaded.

## How it works

- **Website** (`index.html`, served by GitHub Pages) — the attendee pages and the staff dashboard.
- **Server program** (Supabase Edge Function `cpd`) — runs the same rules engine (`src/core.js`) on the server against one shared copy of the event data. Every change runs inside a database transaction that locks the data first, so simultaneous bookings never overbook.
- **Who sees what** — attendees see places left and only their own booking (via a private link). Staff sign in with email and password; their role comes from the staff list. The PA/Reception role does not receive the audit history or the anonymous feedback answers.
- **Practice mode** — a separate copy with fictional attendees and a simulated clock, saved on one device only, for rehearsing event night.

## Staff accounts

Two things are needed for each staff member:
1. **A role** — the administrator adds their name, email and role in **Settings → Staff access**.
2. **A login** — in Supabase: **Authentication → Users → Add user → Create new user**, the same email and a password, with *Auto Confirm User* ticked.

## Files

| Path | What it is |
| --- | --- |
| `index.html` | The built website. Do not edit by hand — run `build.py`. |
| `src/core.js` | Rules engine: capacity, deadlines, waiting list, permissions, certificate eligibility. |
| `src/remote.js`, `src/config.js` | Connection to the shared database and staff sign-in. |
| `src/app.js`, `src/styles.css`, `src/template.html` | User interface. |
| `src/seed.js`, `src/store.js` | Practice mode: fictional scenarios and on-device storage. |
| `src/pdf.js` | Certificate, attendance register, evaluation survey, registration form, check-in list. |
| `server/` | Server program source (`handler.js`), Supabase entry point (`index.ts`), initial staff list. |
| `supabase/functions/` | Generated by `build.py` from `server/` and `src/core.js` — deployed to Supabase. |
| `.github/workflows/deploy-supabase.yml` | Deploys the server program when it changes. Needs the `SUPABASE_ACCESS_TOKEN` secret. |
| `tests/` | Rules, server and browser tests. |
| `BUILD-NOTES.md` | Decisions taken and known limits. |

## Build and test

```
python3 build.py                         # writes index.html and supabase/functions/
node --test tests/core.test.js           # rules tests
PGURL=... WAPCPD_LIB=... node --test tests/server.test.mjs   # server tests (local Postgres)
WAPCPD_LIB=... python3 tests/e2e.py      # browser tests, practice mode
PGURL=... WAPCPD_LIB=... python3 tests/e2e_remote.py         # browser tests, shared database
```

`WAPCPD_LIB` points to a `node_modules` folder with `postgres@3.4.4`, `jspdf@2.5.1`, `qrcode-generator@1.4.4` and `jsqr@1.4.0`.
